## Plans and reports

- Do not output substantial implementation plans, audit reports, review reports,
  investigation findings, or completion reports only in the terminal.
- Also save each substantial plan or report as a Markdown file in `docs/development/`.
- Create the directory if it does not exist.
- Use descriptive filenames, for example:
  - `docs/development/implementation-plan.md`
  - `docs/development/contract-audit.md`
  - `docs/development/test-review.md`
  - `docs/development/implementation-report.md`
- When updating an existing piece of work, update the relevant report rather than
  creating unnecessary duplicate files.
- Keep the complete useful report in the Markdown file.
- The terminal response may contain a concise summary plus the path to the saved report.
